# Birr

A private personal-finance tracker for Ethiopia that runs as a Telegram bot + Mini App. It ingests telebirr (`127`) and CBE SMS, parses them into transactions, and shows balances, budgets and insights in ETB.

## Layout

```
apps/server      Hono API + grammY bot + SMS ingest + cron (one Vercel function in production)
apps/miniapp     React + Vite + Tailwind Mini App
packages/parser  SMS templates per sender, fixtures, tests
packages/core    Pure logic: reconciliation, transfer matching, budgets, Ethiopian calendar…
packages/shared  Shared types and default categories
drizzle/         SQL migrations (generated by drizzle-kit)
scripts/         build-vercel.mjs (Vercel Build Output API)
```

## Hosting

Production runs on **Vercel + Supabase** (both free tiers): see [DEPLOY.md](DEPLOY.md).
To record SMS automatically from your iPhone, see [SETUP.md](SETUP.md).

### Database

Postgres in a private `birr` schema with row-level security enabled on every table, so Supabase's
public Data API can't read it. Locally and in tests the same schema runs on **PGlite**, an in-process
Postgres, so there's no database server or Docker to install.

## Local development

Requires Node ≥ 22 and pnpm (`npm i -g pnpm`). Use a **separate test bot** from @BotFather. Local dev
runs in polling mode and refuses to take over a bot that has a production webhook.

```sh
pnpm install
cp .env.example .env         # test bot's BOT_TOKEN, ALLOWED_TELEGRAM_IDS, DATA_ENCRYPTION_KEY
pnpm dev                     # API+bot on :8787 (polling), Mini App on :5173; data in data/pglite
pnpm test
```

With `DATABASE_URL` unset, data lives in `data/pglite/` (gitignored). Migrations run on start.

### See the app with fake data, in a normal browser

```sh
# in .env: NODE_ENV=development, DEV_AUTH_TELEGRAM_ID=<one of ALLOWED_TELEGRAM_IDS>
pnpm seed                               # ~3 months of realistic fake telebirr/CBE SMS (add --reset to redo)
pnpm preview                            # API on :8787 with the dev login; the bot is NOT started
pnpm --filter @birr/miniapp dev         # then open http://localhost:5173
```

The seed writes SMS in the real formats and runs them through the real pipeline, so categories, rules,
budgets, one deliberate "missing SMS" gap and internal transfers all show up. It refuses to run against a
`postgres://` database, so fake data can't reach production.

Telegram only opens Mini Apps over HTTPS. To try the Mini App inside Telegram during development,
tunnel the Vite port (it proxies `/api` and `/ingest` to the server):

```sh
cloudflared tunnel --url http://localhost:5173
```

Put the printed `https://….trycloudflare.com` URL in `MINIAPP_URL` and `PUBLIC_URL`, restart, and send
`/start` to your test bot.

To check the production build locally: `node scripts/build-vercel.mjs` writes `.vercel/output/`.

## Schema changes

Edit `apps/server/src/db/schema.ts`, then `pnpm db:generate`. Production applies migrations during the
Vercel build; local dev applies them on start.
